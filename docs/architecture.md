# Архитектура и конвейер

## Архитектура

```
браузер ──► api (FastAPI: /api/v1, интерфейс, /health, /metrics) ──► db (Postgres 16)
               │ задачи (таблица в БД)                                   ▲
               ▼                                                         │
            worker (тот же образ) ───────────────────────────────────────┘
               ├─ CPU: LibreOffice, PyMuPDF, RapidOrientation, отбор страниц F40
               ├─ GPU: классификатор типа страницы (LiLT-ruBert + SigLIP2, ~3,5 ГБ), RapidOCR
               └─ HTTP, OpenAI-совместимый API ──► llm (vLLM 0.29, Qwen3.8-27B FP8)
backup (pg_dump каждые 15 мин) ──► том inspector_backups
```

| Сервис | Профиль | Образ | Назначение |
|---|---|---|---|
| `db` | всегда | `postgres:16-alpine` | процессы, файлы, страницы, метки страниц, находки, решения, аудит, очередь задач, реестр моделей |
| `api` | всегда | `inspector` (этот репозиторий) | REST API `/api/v1`, интерфейс, Swagger `/api/docs`, `/health`, `/metrics` |
| `worker` | всегда | тот же `inspector` | конвейер из 11 этапов; итерации дообучения классификатора и отбора страниц; повторы отправки в РиН; сверка SHA-256 хранилища (раз в сутки); отчёт по дообучению (раз в неделю) |
| `backup` | всегда | `postgres:16-alpine` | резервные копии БД: `pg_dump` каждые 15 мин, хранение 30 дней |
| `llm` | `h100` | `vllm/vllm-openai:v0.29.0` | Qwen3.8-27B FP8: тип страниц, где классификатор не уверен; перечитывание отобранных сканов; извлечение значений; судья; верификатор |

Хранилище — том `inspector_data` (`/var/inspector`): оригиналы по SHA-256, PDF после конвертации, кэш разбора по хешу
файла (слой, слова RapidOCR, текст модели, типы страниц), снимки протоколов, версии классификатора и отбора страниц
после дообучения (`models/page-cls/…`, `models/page-router/…`). Повторная загрузка того же файла заново не разбирается.

Образ `inspector`: Python 3.12, torch 2.11 (CUDA 12.8) и transformers 5.17 для классификатора, LibreOffice без GUI
(DOC/DOCX/RTF/ODT/XLS/XLSX → PDF), `bsdtar` (zip/7z/rar), шрифты DejaVu, Liberation, Carlito и Caladea (метрически
совместимы с Arial/Times/Calibri/Cambria), собранный интерфейс. Модели RapidOCR, RapidOrientation и отбора страниц F40
лежат в образе (`inspector/resources`). Каталог модели классификатора монтируется с хоста только на чтение
(`./models/page-cls` → `/models/page-cls`). Веса Qwen и SigLIP2 берутся из кэша Hugging Face хоста. Процесс работает
от uid 1000.

## Конвейер: как находится расхождение

Проверка проходит 11 этапов по порядку (`inspector/pipeline/runner.py`, `STAGES`). Разбор страниц, OCR и ответы
Qwen на тип страницы кэшируются по SHA-256 файла, ответы извлечения — по хешу текста страницы и параметров.

| № | Этап | Код / модель | Что на входе → что на выходе |
|---|---|---|---|
| 1 | Приём (`intake`) | код | файлы и архивы (рекурсивно, cp866-имена) → уникальные PDF; DOC/DOCX/XLS(X)/RTF/ODT, картинки, XML → PDF; дубли, мусор, `.sig`, манифест организатора; битые и неподдерживаемые файлы — статус с причиной |
| 2 | Страницы (`pages`) | код, PyMuPDF | PDF → текстовый слой и слова с рамками в долях видимой страницы (CropBox + Rotate); страница без слоя или с мусорным слоем → в OCR |
| 3 | OCR (`ocr`) | RapidOCR PP-OCRv5 mobile, GPU или CPU | страницы без слоя → слова с рамками и текст в порядке чтения; повёрнутый скан сначала выпрямляется |
| 4 | Тип страницы (`classify`) | классификатор (GPU) + Qwen3.8 | вид листа или тип документа ИД (32 класса), «первая страница документа», раздел (АР, КР…), качество скана. Уверенные страницы размечает классификатор, остальные — Qwen3.8 по картинке и тексту ([классификатор типа страницы](ml-retraining.md#классификатор-типа-страницы-с-дообучением)) |
| 5 | Документы (`documents`) | код | страницы → документы: ИД — поток актов по «первой странице», ПД/РД — том; паспорт из штампа (шифр, лист, изменение); стадия по содержимому; актуальная редакция тома по шифру и сходству первых листов |
| 6 | Отбор (`select`) | модель F40 (CPU) + код | параметр × стадия → 40 страниц-кандидатов: список обучаемой модели и список по словам названия, шаблону значения и рецепту матрицы сливаются по рангам (RRF, k = 60) |
| 7 | Точный текст (`reocr`) | Qwen3.8 | сканы, попавшие в отбор, модель перечитывает целиком (плитки 200 dpi, 1800 px); при сбое остаётся текст RapidOCR |
| 8 | Извлечение (`extract`) | Qwen3.8 | страница + её параметры → значения {локация, значение, цитата}; цитата обязана быть на странице; рамка значения — по словам слоя или RapidOCR |
| 9 | Сопоставление (`compare`) | Qwen3.8 | значения параметра ПД/РД/ИД → группы по локациям и вердикт по триггеру матрицы (модель ссылается только на индексы найденных значений) → верификатор перечитывает контекст → статусы ТЗ |
| 10 | Свободный поиск (`freesearch`) | код | экспликации помещений и квартирография ПД↔РД на листах АР → гипотезы (SUSPICION) с уверенностью 0..1 |
| 11 | Протокол (`protocol`) | код | версия протокола (JSON + PDF по Приложению 2), сабмит по схеме организаторов |

**Текст сканов: RapidOCR на всё, модель — на отобранное.** Для типа страницы и отбора хватает текста RapidOCR (модели
в образе). Точный текст нужен только страницам, которые пойдут в извлечение: их после отбора перечитывает
Qwen3.8. На сканах актов и сертификатов Qwen3.8 прочитала 94 % слов, RapidOCR — 80 %. Повёрнутый скан перед RapidOCR
выпрямляется: угол берётся, только если согласны голоса строк RapidOCR и RapidOrientation. На 300 сканах корпуса
повёрнутых было 15 %; правило нашло 82 % из них, лишних поворотов — 0,7 %; на повёрнутых RapidOCR находит 78 % слов
вместо 46 % (`RAPIDOCR_ORIENT=false` — выключить). Пустая плитка или битая страница оставляют без рамок только себя.

RapidOCR считает на GPU пулом процессов (`RAPIDOCR_GPU=true`, 2 процесса, у каждого свой движок и предел памяти;
~11 ГБ рядом с vLLM). Текст тот же, что у пула на CPU, а один процесс на GPU почти не быстрее пула CPU — поэтому пул.
4 процесса быстрее двух, но рядом с Qwen FP8 не помещаются (память GPU — в [развёртывании](deployment.md#быстрый-старт-стенд-жюри-1h100)). Если CUDA для
onnxruntime недоступна, в журнал пишется ошибка и распознавание идёт пулом CPU; лист, не влезший в предел
памяти, пересчитывается на CPU.

**Отбор страниц F40 — обучаемая модель.** Для каждого параметра матрицы модель оценивает, есть ли на странице его
значение: текст страницы превращается в признаки TF-IDF, к ним добавляются стадия, тип и раздел страницы, решает
логистическая регрессия. В извлечение идут 40 страниц: лучшие по оценке модели вместе со страницами, найденными по
словам названия и шаблону значения. На объекте, которого не было в обучении, так находится 42,5 % значений против
24,7 % при отборе только по словам, при той же точности. Модель дообучается в сервисе на решениях экспертов по
кандидатам ([отбор страниц с дообучением](ml-retraining.md#отбор-страниц-с-дообучением)). Артефакт —
`inspector/resources/router` (версия `router@b6c996c9`); `SELECT_MODE=lexical` — только отбор по словам.

`EXTRACT_WITH_IMAGE=true` добавляет в извлечение картинку OCR-страницы. По умолчанию выключено: прироста
качества не дало.
