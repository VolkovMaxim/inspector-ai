# Отступления от ТЗ и ограничения

## Отступления от ТЗ и почему

| ТЗ | Сделано | Почему |
|---|---|---|
| Бэкенд на Node.js | Python 3.12 + FastAPI | Q&A организаторов: разрешены совместимые аналоги стека. Конвейер ML на Python — один язык для API и конвейера |
| RabbitMQ | очередь задач — таблица в Postgres: `worker` забирает задачу, пишет heartbeat; задачу без heartbeat 15 мин перезапускает, всего 3 попытки | Q&A: очередь можно заменить другим надёжным механизмом фоновых задач. На один стенд хватает; задачи переживают перезапуск вместе с БД |
| Redis для кэша | кэш разбора по SHA-256 файла на диске (`/var/inspector/cache`) | тот же файл второй раз не разбирается, кэш переживает перезапуск |
| ТЗ 9.4: итерация дообучения — не менее 100 подтверждённых нарушений, проверка на 30 % данных, откат при падении F1 более чем на 5 % | Дообучаются две модели. Классификатор типа страницы — на правках разметчиков (любое число правок); оценка — на правках и на замороженном наборе приёмки (верный тип, порог 1 п. п.). Отбор страниц F40 — на решениях экспертов по кандидатам (любое число решений); оценка — доля страниц со значением в первых 40. Версии утверждает ML-инженер, откат — к любой утверждённой. Qwen3.8 не дообучается: решения по кандидатам копятся ещё и в GOLD (версии, разбиение по объектам, хеши) и в недельном отчёте | Q&A №24: для зачёта достаточен воспроизводимый контур с журналом метрик, ручным утверждением и откатом. Правки типов страниц разметчик делает за минуты, итерация идёт секунды — контур можно показать на стенде целиком |
| УКЭП | заглушка | подписание — вне объёма прототипа |
| ELK | логи JSON в stdout (`docker logs`, ротация), метрики Prometheus `/metrics` | сборщик логов подключается без изменения кода |
| Интеграция с ИАИС РиН | заглушка: приёмник `/api/v1/mock-rin/receive` с общим токеном (`RIN_TOKEN`, `Authorization: Bearer`), повторы через 1 / 5 / 15 мин, статус `PENDING_SYNC` при сбое | реального API РиН нет |
| TLS | обратный прокси перед стендом | стандартная практика, сертификаты — забота стенда |

## Ограничения и что не проверено

- **PyMuPDF (разбор PDF) распространяется по AGPL-3.0** или по коммерческой лицензии Artifex. Это не модель, и Q&A
  №23 его не касается. Но при передаче решения для пилота AGPL требует раскрывать исходники всего сервиса. До пилота
  нужно выбрать: выполнять AGPL, купить лицензию или заменить библиотеку.
- **Ревизии весов Qwen не закреплены**: `prefetch_models.sh` и vLLM берут текущую `main`. Проверенные ревизии:
  `Qwen/Qwen3.8-27B-FP8` — `017b9c7af6b5689d5dd426a76e0bc077eb5ca20a`, `unsloth/Qwen3.8-27B-NVFP4` —
  `f0b7c9e722f5565102fff8481c99e4d86ae099c7`. SigLIP2 и классификатор страниц закреплены по ревизии.
- **Qwen FP8 на H100 (по умолчанию).** Полный прогон Алтуфьевского и замеры качества сделаны на NVFP4 с 4
  процессами RapidOCR. На FP8 замерены старт, память vLLM и разметка типа 300 страниц; память стенда с FP8 и 2
  процессами RapidOCR (~70 из 81,5 ГБ) сложена из замеров частей. Запасной вариант — NVFP4 ([быстрый старт](deployment.md#быстрый-старт-стенд-жюри-1h100)).
- **Классификатор страниц** не видит заголовок страницы: поэтому первые страницы ИД размечает Qwen. В одиночку
  модель уступает Qwen3.8 (284 против 333 из 409). Признак качества скана у модели не проверен. Скорость на CPU не
  измерена. После нескольких итераций
  дообучения worker держит в памяти до 4 загруженных версий модели.
- **Сбой модели на этапе reocr не останавливает проверку**: сканы остаются с текстом RapidOCR, этап отмечается
  выполненным. Недоступный отдельный `OCR_URL` виден в `/health` как `degraded`.
- `PAGE_CLASSIFIER_DEVICE=cpu` переводит на CPU только разметку: итерация дообучения всё равно считает на GPU, если
  worker её видит. Чтобы классификатор целиком ушёл на CPU, закомментируйте `COMPOSE_FILE`.
- Прямая совместимость CUDA (`VLLM_ENABLE_CUDA_COMPATIBILITY=1`) для драйверов < 580 не проверена.
- Свободный поиск (гипотезы вне матрицы) пока охватывает только экспликации помещений и квартирографию в АР.
